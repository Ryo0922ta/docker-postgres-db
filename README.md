## docker 動かし方

up と startの違いはズバリ元々あるものをビルドするか、0から作り直すか

`docker compose up -d (0からイメージからビルドしてコンテナを起動.またはイメージがなければ取得してコンテナ起動)`
ただし、仮にすでにイメージがある場合はそれを読み取って起動のみをしてくれる

`docker compose start`
コンテナの電源をつけるだけのイメージ.



## docker 止め方

コンテナを一時的に眠らせて残す場合、コマンドの使い分けが命運を分けます。

`docker compose stop （推奨：残したいとき）`
コンテナの「電源を切る」だけです。コンテナの存在もデータもそのまま残るため、ブランチを切り替えて戻ってきたときにすぐ再開できます。ポート競合も起きません。

`docker compose down （コンテナは消えるが、データは残る）`
コンテナという「器」そのものを削除します。ただし、今回のように volumes の下に name: postgres_data_learning と名前を明示していれば、器は消えてもデータ（中身）はDockerの中に安全に残ります。 次回 up したときにデータが復活します。

`⚠️ docker compose down -v （絶対ダメ）`
-v オプションをつけてしまうと、明示してあるボリューム（データ）ごと地球上から完全に消去されます。学習の成果がすべて吹き飛びますので、これだけは絶対に避けてください。
